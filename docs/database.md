# 🗄️ Database Architecture

This document describes the database used by **Wildfire Sentinel AI**.

The system uses **PostgreSQL** as the main database and **PostGIS** for geospatial data.

---

## 📌 Overview

| Workflow | Main purpose | Tables used |
|---|---|---|
| 01 Core (WhatsApp) | Wildfire report intake, geolocation and escalation | `forest_incidents`, `conversation_state` |
| 02 Alertas (Clima) | Weather-based wildfire risk scoring and alerts | `fire_alerts` |
| 03 Dashboard (Métricas) | Daily summary of the last 7 days | Reads `forest_incidents` and `fire_alerts` |

---

## 🔥 `forest_incidents`

Stores every wildfire report received over WhatsApp (text, image or location).

| Column | Type | Description |
|---|---|---|
| `id` | UUID | Primary key |
| `case_id` | TEXT | Human-readable identifier, e.g. `FOR-1782141334-AB12C` |
| `incident_type` | TEXT | `INCENDIO` |
| `description` | TEXT | Short summary generated by Gemini |
| `priority` | TEXT | `ALTA`, `MEDIA`, `BAJA` |
| `reporter_name` | TEXT | WhatsApp profile name |
| `reporter_phone` | TEXT | WhatsApp phone number |
| `latitude` | DOUBLE PRECISION | Latitude |
| `longitude` | DOUBLE PRECISION | Longitude |
| `location` | GEOMETRY(Point, 4326) | PostGIS point built from the coordinates |
| `parcela` | TEXT | Parcel or area reference, if given |
| `status` | TEXT | `PENDIENTE_UBICACION` or `ABIERTO` |
| `ai_classification` | TEXT | AI classification result |
| `assigned_to` | TEXT | Assigned supervisor or team |
| `metadata` | JSONB | Subtype, original message, geocoded location, media info, channel, etc. |
| `created_at` | TIMESTAMPTZ | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Last update timestamp |

Relevant `metadata` keys:

| Key | Description |
|---|---|
| `subtipo` | `HUMO`, `FUEGO`, `RAYO`, `COLILLA`, `QUEMA_ILEGAL`, `BARBACOA`, `MAQUINARIA`, `LINEA_ELECTRICA`, `FOCO_TERMICO`, `OTRO_RIESGO` |
| `mensaje_original` | Message as received |
| `ubicacion_nombre`, `ubicacion_completa`, `ubicacion_municipio`, `ubicacion_provincia` | Reverse geocoding result |
| `ubicacion_texto` | Place name given by the user or detected in the image |
| `original_message_type` | `text`, `image` or `location` |
| `media_id`, `media_type`, `caption` | WhatsApp media data |
| `requiere_escalado` | Whether the case required supervisor escalation |
| `coordenadas_actualizadas_en`, `coordenadas_fuente` | Set when a pending case receives its location |

---

## 💬 `conversation_state`

Keeps track of cases waiting for a location. When a user reports a fire without location, a row is stored here; when the user sends coordinates, a WhatsApp location or a place name, the case is updated and the row is deleted.

| Column | Type | Description |
|---|---|---|
| `user_phone` | TEXT | WhatsApp phone (primary key, one pending case per user) |
| `current_state` | TEXT | Reserved for future multi-step flows |
| `pending_case_id` | TEXT | `case_id` waiting for a location |
| `pending_type` | TEXT | Reserved; the type is read from `forest_incidents` |
| `context_data` | JSONB | Reserved for extra context |
| `created_at` | TIMESTAMPTZ | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Last update timestamp |

---

## 🌦️ `fire_alerts`

Stores every weather reading and the computed wildfire risk.

| Column | Type | Description |
|---|---|---|
| `id` | UUID | Primary key |
| `zone_name` | TEXT | Monitored zone (from OpenWeatherMap) |
| `temperature` | NUMERIC | Temperature (°C) |
| `humidity` | NUMERIC | Humidity (%) |
| `wind_speed` | NUMERIC | Wind speed (km/h) |
| `fire_risk` | TEXT | `BAJO`, `MODERADO`, `ALTO`, `EXTREMO` |
| `alert_sent` | BOOLEAN | `true` when an alert was sent to the crews |
| `metadata` | JSONB | Risk score, raw weather data and timestamp |
| `created_at` | TIMESTAMPTZ | Creation timestamp |

## 📍 PostGIS

The `set_location_from_coordinates()` trigger in `database/triggers.sql` builds the `location` point from `latitude` and `longitude` on every insert or update of `forest_incidents`. The Core workflow also writes the point explicitly when a pending case is completed.

```sql
NEW.location := ST_SetSRID(ST_MakePoint(NEW.longitude, NEW.latitude), 4326);
```

## 📊 Metrics

The dashboard workflow computes:

- Total reports and reports by type and priority (last 7 days)
- Alerts sent by risk level (last 7 days)
- Top 5 locations by number of reports (last 30 days), using municipality, place name, text location or parcel

The results go to Google Sheets, Gmail and WhatsApp.

## 🛡️ Security notes

- Don't expose real user data in public repositories.
- Use demo data for screenshots.
- Store secrets in environment variables or n8n credentials.
- Sanitize exported n8n workflows (`pinData`, phone numbers) before publishing.
- Enable Row Level Security if the database is shared between organizations.
